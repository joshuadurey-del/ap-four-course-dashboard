Cross-course HOLD

Stage 4 requires a course-bound delivery package

The publishing mechanism may be reusable; authorization and proof are not. A course does not leave Validate & seal until its exact accepted bytes are bound to its own manifest, action authorization, planned or supplied IDs, readback and recovery rules, and learner-surface projection. Another course's IDs, digest, access receipt, or execution authority cannot clear this gate.

Internal review is a separate gate after serving-layer readiness. Human learning-science or subject-matter findings loop back into build, validation, or publication work; persona and model simulations do not clear that gate.

Before publication

  • Pin the accepted course revision and complete object census.
  • Seal the course-owned package and exact attempted action.
  • Name one writer, checkpoint/resume behavior, exact readback, and compensating recovery.
  • Bind learner-surface mapping, registration, deployment, and the final signed-in walk.

Filing route

  • Continue on an existing owning issue when it already covers the same missing contract.
  • Open a new filing only after current canonical bytes prove BLOCKED_CONTRACT and the duplicate/filing check is clean.
  • Ask for one missing contract and name the exact event that clears the hold; do not file a generic access request when the shared mechanism already exists.
  • Each course page names its current blocker thread. Delivery work starts only after that course's present validation gate clears.
