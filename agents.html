How to read it

Trace a claim
Start from any sentence in the standings, find its claim_id in the manifest, and follow the evidence entries.
Check what you can access
evidence_access tells you what you can verify yourself: SHARED = live URL or Ilma-readable repo; ILMA_HUMAN_ONLY = the evidence repo (browser yes, bot tokens no); SHARED_AFTER_INVITE = Langfuse; JOSH_MACHINE_ONLY = named local artifact with a durable-copy plan; NONE_YET = planned work, no receipt can exist.
Check freshness
Every claim carries its own date — observed_at for an OBSERVED claim, status_at for a PLANNED or BLOCKED one. Age it against that field, never against the manifest snapshot: republishing the file does not refresh a claim. A claim older than 48 hours with no successor receipt is a question, not a fact — unless it carries settled: true, which marks terminal history (a measurement or ruling that is permanently closed, like the retired local judge). Settled claims keep their true dates and are exempt from the staleness clock. observed_note holds any hand-written qualifier, including "midnight assumed" where the source recorded only a date.
Open Langfuse evidence
Langfuse lives at us.cloud.langfuse.com, project incept-durey — accept the org invite first or the trace links 404. Claims with Langfuse evidence carry direct trace URLs in data.json; the full reading guide is at the bottom of the accounting .md.
Cross-check the receipt
Cross-check any Langfuse record against the matching GitHub evidence branch by item id or hash — both are written from the same receipts.

Byte integrity (sha256)

Same convention as the Incept content-factory pages: every machine-readable file is published with its digest. Fetch a file, hash it, compare — if the digests match, you hold exactly the bytes this site published. Verify with curl -s <file url> | shasum -a 256. The manifest is hashes.json, regenerated on every commit by a git hook (it cannot hash itself).
