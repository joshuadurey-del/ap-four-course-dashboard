Recovery lessons

A reproducible process catalog: each lesson names a trigger, observable failure, missing control, implemented control, and verifier. Ownership sets priority; blame does not close a process gap.

How a lesson earns a place here

trigger → observable failure → missing control → implemented control → verifier

  • Build inside the canonical sequence. Trigger: downstream work begins while upstream authority is unresolved. Observable failure: multiple artifacts can each look green while no one can say what closes the course. Missing control: one active lifecycle state with a defined postcondition. Implemented control: the ASAP route is content → p3 → p5 → p6 → p7 → p8, and each course displays only its re-earned position. Verifier: every handoff returns the named state or phase, canonical surface, production verifier, residue, owner, and next phase.
  • Stop legacy automation at a new boundary. Trigger: an older retry continues after the owner replaces the operating sequence. Observable failure: work that belongs after scope and inventory is pulled back into stabilization. Missing control: retry scope was not rebound to the new gate. Implemented control: the gate remains on hold until the retry is stopped or rescoped. Verifier: live issue readback shows a terminal writer-free transaction before the next gate opens.

Factory-canonical operating rules

Open the durable cross-course audit findings.

  • Read the committed factory contract before acting. If the route exists, use it exactly. If it does not, file the gap; do not bridge it locally.
  • Bind inherited factory evidence instead of repeating it. Generation-time QC and hosted grader calibration keep their value when the exact candidate and provenance are linked; an empty downstream folder does not erase them.
  • Measure the review denominator before authoring. Pin blueprint scope, compute current coverage, and generate only the highest-value missing work. Never shrink the denominator after seeing a low score.
  • Keep states separate. Prepared, factory-accepted, merged, deployed, and released are different claims with different evidence.
  • Unknown stays unknown. Missing provenance or an unread receipt blocks credit; prose cannot fill the gap.
  • Approvals are scoped. Investigation, CI success, or a prior owner go does not authorize a new write, paid run, filing, merge, deletion, or release.
  • One writer owns each lane. Other agents may inspect and report, but they do not mutate the same checkout or state.

Safe cleanup sequence

  • Quarantine only exact SHA-verified targets after checking for live processes and locks.
  • Prove the canonical replacement or record a factory contract gap.
  • Retire any status mark that depended on the old machinery.
  • Delete only owner-approved rows whose replacement preconditions passed.
  • Run the residue scan twice and keep remaining blockers explicit.

Current posture: the 16-row purge manifest is approval-gated. No hand-rolled target should be deleted merely because it appears on the list.
