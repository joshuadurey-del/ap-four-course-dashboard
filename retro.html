Course-creation retro

How AP courses have actually been built, mined 2026-08-26 from the fleet's full history: three process generations, an eleven-stage map with proof status for every stage, the detours and what they cost, and the measured distance to the end state — a course build an AI system can run end to end, quickly, with a receipt at every step. The historical mining stays anchored to its dated corpus; the current lifecycle edge below is reconciled through 2026-08-31 02:23Z.

End state

The build this page aims at

The target is a course build that goes from scaffold to release on the first pass, fast, and provably: deterministic operators walk the stages, trained models speed up the content substeps, and every step closes with a receipt that binds exact bytes. The mined history says three things about that target.

  • The process is becoming code, not judgment. Publication runs through one runbook corridor with named operators, typed hold-and-recover branches, and closure packets. Whatever is proven once becomes replayable. On 2026-08-31, the proven HumGeo Phase 1-3 walk was folded into three registered wrappers: bank validation, native-assets build, and the landing ceremony. The same day's needs-a-human machinery added a ledger, public projection, self-test, and operator nudges rather than hiding exceptions in prose.
  • Speed compounds through worked examples. AP Lang's content build ran 2026-06-04 to 07-16 in its own repo (101 commits). Its native TimeBack publication operators were then built and proven across four days, 2026-08-14 to 08-17: dry-run publisher (#697), sealed 2,070-operation plan (#714), offline-proven executor (#716), live undo canary (#718), full 108-lesson catalog (#722). AP Lit then replayed that corridor — authority census, plan, live catalog, dark settlement, first learner start — in a single day, 2026-08-20 (#811). A proven, named operator makes the next course's step nearly free; an unproven step costs weeks the first time, whoever runs it.
  • The unproven tail is named, not vague. No course anywhere has a receipted content import, a complete canary-enrollment run, a full learner acceptance, or a release. Those are the exact steps standing between today's process and end-to-end automation.

The retro — five lessons the fleet actually paid for

  1. Make the import a receipted step.

    In both successful courses, nobody can name the commit that moved finished course content into the platform tree; AP Lang's 26 course files simply appear in the live listing. The most-asked question in course work — how does content actually get in — had no receipted answer even in the wins. The rule now: the stage-E closure packet must contain the import receipt itself, meaning a named commit or PR plus a tree listing.

  2. Run every known check at generation, never later.

    AP Lang enforced answer balance during generation, in its first build week. HumGeo ran the same class of check after three gates had already closed, and paid a triple reopen: 203 records, then 70 more the first repair missed, then the profile bind redone twice. Same check, different position, weeks of difference. This is the single strongest cost lesson in the data.

  3. A closure is only as stable as the bytes it binds.

    HumGeo's profile-and-source bind closed twice because upstream repairs kept changing the accepted source underneath it. A closure receipt binds exact digests, and an upstream change reopens the earliest affected gate automatically. That reopening is a normal branch of the process, not an emergency.

  4. Name one operator per phase.

    AP Lit built one named module per runbook phase — authority census, publisher, executor, acceptance — and its run replays cleanly. AP Lang folded its early phases into generic modules, and parts of its history can no longer be attributed. HumGeo then proved the rule again at Phase 4: the native asset layer has no plan builder, so sealing stops at the explicit issue #919 seam instead of improvising a local route. One hazard rode along: internal phase numbering collided with the master runbook's, so phase names now come from the master runbook only.

  5. One corridor, said on page one.

    A parallel Platform3 ingest track stayed alive the whole period and received a commit the very morning of the mining pass (#860, 2026-08-26). Platform3 is not a publication corridor. Without that warning stated up front, anyone reading raw history conflates the two tracks; both traces had to be explicitly split to stay coherent.

Detours are typed, not emergencies

HumGeo's walk logged nine distinct wrong-turn-and-recovery pairs; Lang and Lit had their own. Every one fits a small typed set of recovery classes, which is what turns a detour into a bounded cost instead of a crisis. The five classes the mining produced:

  • A late verifier invalidates closed gates. Reopen the earliest affected gate for exactly the failing records.
  • Upstream bytes moved under a closure. Rebind on fresh digests.
  • An approval gap. The work is ready but the remote write is not authorized: hold, name the owner, resume only on the named word.
  • A missing factory contract. The needed route is not wired for this course: classify it, file the gap, hold for the go. Never adapt a runner locally.
  • An identity or learner-state fault at acceptance. Record the no-go, repair isolation, retry the acceptance.

The handbook draft has since grown this into eleven typed hold classes. The standing operating rules distilled from recovery work live on the Lessons page; this page maps where in the history each class was paid for.

The training question, measured

The end state needs both halves: a deterministic process and fast content. A read-only census on 2026-08-26 measured what is actually trainable today.

  • The process is code, not a training corpus. Three full course histories yield 167 process rows. That is a step table for a controller, and thousands of examples short of training data for a process model. A process model is also not needed: stages, entry conditions, receipts, and hold classes are already deterministic.
  • Content repair is trainable now. The census found 431 explicit fail-then-fix pairs with full content inline: the failing item, the structural repair, and the retry. That clears the pilot-scale bar for a repair model.
  • Verdict prediction is not trainable yet. The current item bank holds 437 passes against 7 fails, because failures get repaired out of the bank. The fail class has to be mined from history; one earlier sweep alone recorded 1,239 fails. That mining round is the named next step.
  • Only HumGeo produced item-level factory verdicts in this pass. APWH, APUSH, and Psychology yielded zero; their verdict evidence has named mining leads, not counts.

What end-to-end automation still needs

  1. Machine-decidable contracts for every stage.

    Entry condition, required artifacts, the receipt that closes it, its hold classes, the reopening target, and resume evidence. The same six fields for all eleven stages.

  2. A first receipted import.

    The next course to close stage E must produce it; that run writes the worked example the whole fleet then reuses.

  3. Worked examples for the tail.

    A complete canary enrollment, a full learner acceptance, and the first release. Each gets mined into this map the day it happens.

  4. The two mining rounds that fix the training data.

    Historical fails for verdict prediction, and verdict evidence for the other three courses.
